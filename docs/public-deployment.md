# 公网合成蜜罐部署边界

`deploy/public/` 是把 DYGK 合成服务开放到公网的准备配置，不是已部署实例。公网测试前必须完成法律、隐私、滥用响应和资源上限检查。

## 范围

- 只运行 `examples/operations` 的合成站点；账户、工单、客户、资产和验收值全部伪造。
- 不启用客户端二进制、`clientChallenge`、`/gateway-check` 或挑战回执；镜像不复制 `experiments/`、`artifacts/`。
- app 容器只读根目录、普通用户、`cap-drop ALL`、无宿主挂载、无外网；数据只写 `dygk-data` 卷。
- 对外只暴露 Caddy 的 80/443；Caddy 终结 TLS，再转发到内部 `app:4181`。
- app 只信任 Caddy 的固定内部地址 `172.30.0.10`；直接暴露 app 或错误配置代理会让封禁落在代理 IP 上。

## 开放前检查

1. 域名已解析到部署机，80/443 可达；Caddy 能完成证书签发。
2. `.env` 不含真实邮箱密码；`ACME_EMAIL` 只用于证书通知。
3. 不发布 app 端口；检查 `docker compose ps` 只有 Caddy 有公网端口。
4. 事件保留、IP 记录、封禁和隐私说明已按所在地要求审核；准备滥用联系人和下线流程。
5. 前置 CDN/防火墙的速率限制已配置；Caddy 本身不做细粒度 per-IP 限流。
6. 不与任何真实业务、真实账户、第三方目标或生产数据库共置。

## 运行边界

- 默认 `block`：首阶段有效提交后封禁 900 秒；封禁是按来源 IP，不保证识别 AI，也不保证阻断全部渗透。
- 公网流量会触发告警、封禁和日志增长；设置磁盘、事件量、会话量和告警阈值。
- 任何“验证代码”“客户端二进制”都不在公网镜像中；档案/验证页仍属于合成蜜罐，可正常记录访问。
- 不在公网实例使用真实凭据；`admin/admin123` 只是合成演示弱口令。
- 停止服务、撤销 DNS、删除数据卷和 Caddy 证书/日志，是完整的下线流程。

## 已知限制

- Caddy 自动 TLS 依赖域名和 80/443；Cloudflare 等 CDN 代理需要额外配置可信代理，否则 app 看到的来源是 CDN。
- SQLite 是单机存储；高流量下需要外部限流和容量监控，不宣称多节点封禁同步。
- 这是研究/演示蜜罐，不是生产安全产品；开放公网不代表对真实业务的安全性承诺。
